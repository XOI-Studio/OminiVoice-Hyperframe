# OmniVoice TTS + HyperFrames render

Two independent services. Each has its own code, tests, requirements and Dockerfile, so they can be built, deployed and scaled separately.

| Folder | Service | Runs on | Docs |
|---|---|---|---|
| [`tts/`](tts/README.md) | `POST /tts`: text to speech in 12 fixed channel voices (OmniVoice), returns a public URL | GPU (Docker, or Modal serverless) | [tts/README.md](tts/README.md) |
| [`render/`](render/README.md) | `POST /render`: renders a HyperFrames project stored in S3 to mp4 (async job), returns a public URL | CPU only, any cheap x86 box | [render/README.md](render/README.md) |

Audio is never generated by `render/`: put the audio (for example the output of `/tts`) in the S3 project folder first.

- API reference for clients: [`llms.txt`](llms.txt) and [`docs/llms/`](docs/llms/).
- Design and plan of the render service: [`docs/specs/`](docs/specs/).

## Shared configuration
Both read the same storage settings from environment variables (copy `.env.example` to `.env` and fill it in):

`S3_BUCKET`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_PUBLIC_BASE_URL`, `S3_ENDPOINT_URL` (only for non-AWS storage such as Cloudflare R2: set `AWS_REGION=auto`), `API_KEY` (optional: empty means no key is needed).

Result URLs only open if the bucket serves the output prefixes (`tts/*`, `renders/*`) publicly; keep `jobs/*` and your sources private. On AWS that is a bucket policy, on R2 a public bucket URL or custom domain.

## Deploy TTS lên Modal (hướng dẫn chi tiết)

Modal chạy `tts/` trên GPU **chỉ khi có request**, nghỉ thì tắt, tính tiền theo giây. Phần render video (`render/`) chưa có bản Modal; chạy nó bằng Docker trên máy CPU.

**Cần có:** tài khoản [modal.com](https://modal.com) (có thể đăng nhập bằng GitHub), một **phương thức thanh toán** đã thêm trong Modal (bắt buộc để dùng GPU: nếu thiếu, deploy báo `Please add a payment method to use ... GPU functions`), và một bucket S3 hoặc Cloudflare R2 mà file kết quả mở công khai được (xem "Shared configuration" ở trên).

### Bước 1. Cài Modal CLI và đăng nhập
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install modal python-dotenv        # python-dotenv để CLI đọc được file .env
modal setup                            # mở trình duyệt để xác nhận đăng nhập, token lưu ở ~/.modal.toml
modal profile current                  # in ra tên workspace nếu đăng nhập đúng
```
Nên vào Modal → **Settings → Billing** và đặt giới hạn chi tiêu hằng tháng trước khi deploy.

### Bước 2. Điền thông tin lưu trữ
```bash
cp .env.example .env                   # rồi sửa .env
```
Ví dụ với Cloudflare R2 (S3 tương thích): `S3_ENDPOINT_URL=https://<account-id>.r2.cloudflarestorage.com`, `S3_BUCKET=<tên bucket>`, `AWS_REGION=auto`, `AWS_ACCESS_KEY_ID` và `AWS_SECRET_ACCESS_KEY` là khoá R2, `S3_PUBLIC_BASE_URL=https://pub-xxxx.r2.dev` (URL công khai của bucket, bật trong Cloudflare R2 → bucket → Settings). Với AWS S3 thì bỏ `S3_ENDPOINT_URL`, đặt `AWS_REGION` đúng region của bucket. Dùng khoá chỉ có quyền đọc/ghi đúng bucket này, không dùng khoá toàn tài khoản.

`API_KEY` để trống nghĩa là **ai biết URL cũng gọi được**. Muốn bắt buộc khoá, đặt một chuỗi ngẫu nhiên (`openssl rand -hex 24`); khi đó client gửi header `X-API-Key`.

### Bước 3. Tạo secret trên Modal
Secret tên `omnivoice-tts` chứa các biến ở bước 2. Bỏ các dòng trống và comment trước khi nạp:
```bash
grep -vE '^(#|$)|=$' .env > /tmp/modal.env
modal secret create omnivoice-tts --from-dotenv /tmp/modal.env --force   # --force = ghi đè nếu đã có
rm /tmp/modal.env
modal secret list                                                          # phải thấy omnivoice-tts
```
Hoặc không dùng file: `modal secret create omnivoice-tts S3_BUCKET=... AWS_REGION=... AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=... S3_PUBLIC_BASE_URL=... S3_ENDPOINT_URL=...`.

### Bước 4. Deploy
```bash
modal deploy tts/modal_app.py          # chạy từ thư mục gốc repo; đường dẫn file là tts/modal_app.py
```
Lần đầu Modal **dựng image mất vài phút** (cài PyTorch, tải model OmniVoice vào image). Các lần sau chỉ tải lại phần code nên vài chục giây. Kết thúc sẽ in URL dạng `https://<workspace>--omnivoice-tts-web.<region>.modal.run`.

### Bước 5. Gọi thử
```bash
URL=https://<workspace>--omnivoice-tts-web.<region>.modal.run
curl -L $URL/health
curl -L $URL/voices
curl -L -X POST $URL/tts -H 'content-type: application/json' \
  -d '{"text":"Xin chào các bạn.","voice":"narrator_male","format":"mp3"}'
# {"url":"https://pub-xxxx.r2.dev/tts/narrator_male/<hash>.mp3","voice":"narrator_male","format":"mp3","duration_s":2.4,"cached":false}
```
Thêm `-H "X-API-Key: $API_KEY"` nếu bạn đã đặt `API_KEY`. Dùng `-L` để curl theo chuyển hướng của Modal (xem phần xử lý lỗi). Request đầu tiên sau lúc nghỉ chậm hơn vì phải bật GPU và nạp model.

### Vận hành
| Việc | Lệnh |
|---|---|
| Xem log | `modal app logs omnivoice-tts` (hoặc trang Apps trên dashboard) |
| Cập nhật code | sửa rồi `modal deploy tts/modal_app.py` lại |
| Đổi secret | sửa `.env`, chạy lại Bước 3 (`--force`) rồi deploy lại để container mới nhận giá trị mới |
| Đổi GPU | `MODAL_GPU=T4 modal deploy tts/modal_app.py` (một loại = ghim; `L4,T4,A10` = thử lần lượt, mặc định) |
| Tắt hẳn | `modal app stop omnivoice-tts` (URL ngừng hoạt động) |

Biến lúc deploy: `MODAL_GPU` (mặc định `L4,T4,A10`), `MODAL_SECRET_NAME` (`omnivoice-tts`), `MODAL_SCALEDOWN_S` (số giây rảnh trước khi tắt container, mặc định 120), `MODAL_MAX_CONTAINERS` (trần số GPU chạy cùng lúc, mặc định 1, cũng là trần chi phí), `MODAL_APP_NAME` (`omnivoice-tts`).

### Chi phí và hiệu năng
- Khi không có request thì không tính tiền GPU. Khi có request, GPU tính tiền từ lúc container bật đến hết `MODAL_SCALEDOWN_S` giây rảnh sau request cuối.
- Đo thực tế trên một deployment: khởi động nguội 19 đến 29 giây, `/tts` câu ngắn khoảng 4 đến 5 giây (`steps=16`). Con số phụ thuộc loại GPU Modal cấp.
- Giá GPU xem trên trang giá của Modal; mức miễn phí hằng tháng (nếu có) xem ở Billing.

### Xử lý lỗi thường gặp
| Triệu chứng | Nguyên nhân và cách xử lý |
|---|---|
| `Please add a payment method to use ... GPU functions` | Thêm thẻ ở Modal → Settings → Billing rồi deploy lại |
| `Need the python-dotenv package installed` | `pip install python-dotenv` trong venv đang dùng |
| Log: `waiting to be scheduled on a GPU_L4 worker` | Hết công suất loại GPU đó. Dùng danh sách dự phòng mặc định (`L4,T4,A10`) hoặc ghim loại khác bằng `MODAL_GPU` |
| `curl` trả `303` sau khoảng 150 giây | Modal chuyển hướng khi một request chưa xong sau 150 giây (thường là lần khởi động nguội đầu). Gọi lại với `curl -L`; với `/tts` dùng văn bản ngắn |
| `401 invalid API key` | Secret có `API_KEY` nhưng client không gửi `X-API-Key` (hoặc sai). Bỏ `API_KEY` khỏi secret để mở, hoặc gửi đúng khoá |
| URL mp3 trả 404/403 | Bucket chưa mở công khai `tts/*`, hoặc `S3_PUBLIC_BASE_URL` sai |
| `AccessDenied` / lỗi S3 trong log | Khoá R2/S3 sai hoặc thiếu quyền ghi bucket |

## Run the tests
```bash
cd tts && pip install -r requirements.txt -r requirements-dev.txt && pytest
cd render && pip install -r requirements.txt -r requirements-dev.txt && pytest
```
Each service is its own Python project (both name their package `app`), so run pytest inside its folder, not from the repo root.
